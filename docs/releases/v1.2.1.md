The agent can now ask with a form in the terminal. agent86UI, agent86's implementation of Google's [A2UI](https://a2ui.org) 1.0 protocol, comes to the interactive interface: when the model needs a structured answer (pick a plan, fill in a few fields, confirm a step), it draws the form, and you answer it with the keyboard.

A2UI is Google's protocol; agent86 is not affiliated with or endorsed by Google.

## agent86UI in the terminal

```text
┏━ agent86UI · drawn by the agent · plan ━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ Which plan do you want?                                          ┃
┃   ( ) Basic                                                      ┃
┃ › (•) Pro                                                        ┃
┃   ( ) Team                                                       ┃
┃   [ Submit ]                                                     ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
```

- **What it draws:** text, rows, columns, cards, lists, dividers, buttons, text fields, check boxes, choices, sliders (as a number), date fields (as text), and images, video, and audio as a link. Tabs and modals say they are not drawn in the terminal yet.
- **Drawn as the agent's, never as agent86's:** a surface sits in a magenta frame with heavy lines that names the agent, which nothing else in agent86 uses, so a form can never pass for an approval. The newest one sits above the input box; when it is answered or replaced, a copy goes into your scrollback. Hiding reasoning or tool use never hides a surface, since it is a question to you.
- **Answering:** a form the model waits on takes the keys at once. Otherwise, Alt+Up (Option+Up) opens the form on screen once the turn is over, and again goes to the next older one. Tab and Shift+Tab (or Up and Down) move between inputs, Space toggles or picks, Left and Right move a slider, typing edits a field, and Enter on a button sends your answer. Escape dismisses or goes back; Ctrl+C also cancels the turn.
- **Links** ask first: a button that opens a URL shows it and waits for y/n, then opens it with your system's opener, http and https only.
- **Resuming** a session (at start, or with `/resume`) puts its forms back on screen, and Ctrl+O's transcript view ends with the one that is up.
- **Settings:** `[ui] agent86ui = "auto"` (the default, on for every model) or `"off"`, which a project file may set without being trusted; `[ui] agent86ui_remote_media = true` lets a surface's media load https URLs, and needs project trust.

`agent86 run`, `run --json`, the plain loop, piped input, and the ACP server never offer the tool, so their output is unchanged. agent86UI comes to ACP clients in 1.2.2.

## For every model

Trying it on real models (seven hosted ones and a local 27B) led to changes that help embedders too:

- **A form must have something to press.** Only a button whose action is an event sends an answer, so a waiting call whose surface has none is refused before it is drawn, and the prompt says every form needs one.
- **A field beside a message's kind is moved inside it.** `"surfaceId"` next to `"createSurface"`, rather than inside it, was the most common first mistake; it is now moved in, and the result says so. Resumed sessions replay the same way.
- **The prompt carries one complete example call** and says component ids are identifiers (`submit_label`, never `submit-label`).
- **A waiting call that was not answered says so first,** before what it drew.
- **Any tool:** when an array or object argument arrives as a string of JSON that does not parse and the call fails, the error now says where it broke.

On the five-task live check, `gpt-6.2-sol` went from 1 of 5 valid on the first try to 5 of 5, and the local `qwen3.8:27b-mlx` from 2 of 5 to 4 of 5. The numbers, and the decision that `auto` means on for every model, are in [ADR 0005](https://github.com/Maetek-Technologies/agent86/blob/main/docs/adr/0005-agent86ui-a2ui.md). [docs/agent86ui.md](https://github.com/Maetek-Technologies/agent86/blob/main/docs/agent86ui.md#in-the-terminal) has the details.

The `sdk` API, the session, trace, and keyring formats, and everything shared with the Python version are unchanged. The minimum supported Rust version is still 1.94.
