`run` prints just the answer, and a round of security fixes.

## What's new

- **`run` keeps stdout for the answer.** `agent86 run "..." > answer.txt` and `$(agent86 run "...")` now capture only the final answer. The tool calls (`[tool] ...`), what the model says between steps, and agent86's notices go to stderr, dimmed at a terminal, so you still see the work as it happens. The answer appears once it is complete instead of streaming in.
  - `run --output full` gives the old single stream on stdout, and `run --output quiet` prints the answer and nothing else (the summary line still goes to stderr). `AGENT86_RUN_OUTPUT` and `[run] output = "full"` set the default.
  - `run --json` is unchanged, plus a new `final` field holding the answer alone. `output` still has the whole stream.
- **A project's config waits for your trust.** A `.agent86/config.toml` that came with a repository can no longer start MCP servers, send your API keys to another server, or turn approvals off just because you ran agent86 there. At a terminal, agent86 lists those settings, with their values, and asks once. Your answer is remembered until the file changes. Harmless settings (the model, limits, display options) apply either way.
- **The model can't quietly rewrite agent86's own files.** A write into `.agent86/`, a skills folder, or your `~/.agent86` is always asked about, with a warning, even with `--yes` or in auto mode. With nobody there to ask, the write is declined.

## Security fixes

- **Approval prompts show what will really run.** In `run` and the plain loop, control characters in a command or a diff are now shown as symbols (`␍`, `␛`, `<U+202E>`) instead of being sent to the terminal. A model could otherwise draw a harmless command over a dangerous one.
- **Symlinks can't carry a write out of the workspace.** A link whose target didn't exist yet could let `write_file` create a file outside the folder agent86 runs in. Such links are now followed and checked, as the Python version does.
- **Secrets stay out of saved sessions.** When `write_file` or `edit_file` wrote a `${secret:NAME}` into a file that already existed, the diff saved with the session held the real value. It now holds the placeholder, as everything else does.

## If you script agent86

- **Reading `run`'s stdout:** you now get the answer alone. Add `--output full` (or set `AGENT86_RUN_OUTPUT=full`) if your script expects the `[tool]` lines there.
- **CI with a project config that defines MCP servers, providers, or guardrails:** pass `--trust-project` or set `AGENT86_TRUST_PROJECT=1`. Without a terminal, agent86 can't ask, so it ignores those settings and says so on stderr.

## Install

```sh
npm install -g agent86
```

Or download the archive for your platform, extract it, and put `agent86` (or `agent86.exe`) on your `PATH`.
