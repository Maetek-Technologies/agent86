Clients can now see which sub-agent is asking for approval and what is waiting behind it, a session survives agent86 being stopped partway through a turn, and editors can reopen a session without replaying it.

## An approval inbox for parallel sub-agents

- **One question at a time, in order.** When several specialist sub-agents run at once and each needs approval, their questions are asked one at a time, in the order they arrived. Before, the order was whatever thread got there first.
- **Who is asking.** For a client that asks for agent86's state events (`com.maetek.agent86/state`), each permission request from a sub-agent says which sub-agent asks, the card it reports on, the git worktree it works in (if any), and what it has spent so far, alongside the turn's spend and the cost limit.
- **What is waiting.** The same client gets a new `questions` event whenever the queue changes: the question being asked and those waiting behind it, so it can show them as a list.
- **Nothing changes for other clients** or in the terminal interface, which already shows sub-agent approvals in its panel.

## Sessions that survive a stopped agent

- **Saved after every step.** agent86 now saves the session after each step of a turn, not only before and after it. If the process is killed or crashes mid-turn, the steps that finished are kept, and `agent86 run --session <id>`, `agent86 --resume <id>`, or reopening the thread in an editor goes on from them.
- A session cut off this way is marked as still running (`execute`) until a later turn ends. The saved format is unchanged, so the Python implementation can still read it.
- Continuing the interrupted turn itself without a new message is not part of this release.

## Reopening a session without replaying it

- **`session/resume`.** Editors and clients can now reopen a saved session with ACP's `session/resume`, which restores it without sending the conversation back. This suits a client that still shows the conversation, such as one reconnecting. The model sees the whole history either way, and `session/load` is unchanged.

## For client authors

- `initialize` now lists `sessionCapabilities.resume`.
- The asker is sent as `_meta["com.maetek.agent86/subagent"]` on `session/request_permission`, and the queue as state events of kind `questions`; both only to a client with `com.maetek.agent86/state`. The format is described in [the ACP guide](https://github.com/Maetek-Technologies/agent86/blob/main/docs/ACP.md#agent86s-state-an-extension).

`agent86 run` and the terminal interface behave as before, apart from the extra saves.
