The model can now draw interactive UI. agent86UI, agent86's implementation of Google's [A2UI](https://a2ui.org) 1.0 protocol, lets an agent embedded with `agent86-core` show the user a form, a choice, or a confirmation instead of asking in prose, and get a structured answer back. A new crate, [`agent86-ui`](https://crates.io/crates/agent86-ui), is the protocol layer, usable on its own. The CLI is unchanged.

A2UI is Google's protocol; agent86 is not affiliated with or endorsed by Google.

## agent86UI in the library

```rust
let mut agent = Agent::builder()
    .provider(provider)
    .workspace(&workspace)
    .ui(Ui::basic().on_wait(|wait| renderer.wait_for_action(&wait.surface_ids)))
    .build()?;

agent.run_with_events("Help me book a meeting", |event| {
    if let TurnEvent::Ui(message) = event {
        renderer.apply(message); // one validated A2UI message, already redacted
    }
}).await?;
```

- **`AgentBuilder::ui`** declares a renderer and its catalogs (`Ui::basic()` for the specification's basic catalog, or `Ui::new(catalogs)`). The model is then offered `render_ui`, and the system prompt teaches it the catalogs' components and functions. Without a renderer, nothing changes: the tool and its prompt section are not there.
- **Every batch is validated** against the catalogs before anything is drawn. A batch that is not valid draws nothing, and the model gets each problem with its A2UI error code and location, worded so it can fix them and try again.
- **`TurnEvent::Ui`** hands each validated message to your program, after the call's `ToolCall` event and before its `ToolResult`.
- **Answers come back two ways.** A button the user presses later becomes the next user message through `Agent::ui_action`. For a form the task cannot go on without, the model sets `wait`, and `Ui::on_wait` is asked for the user's first action, which becomes the call's result.
- **Resume.** `Agent::surfaces()` returns every surface as it is now. After resuming a session, the surfaces are rebuilt from its history, so a program that reopens can put the user back where they were. Nothing new is stored: the session format is unchanged.
- **Safety, as on every path to the user.** What a surface shows goes through the secret vault's redaction and the egress guardrail. What the user enters goes through the vault and the ingress guardrail. A password field is refused, and the model is pointed at `request_secret` instead. Media loads only from `data:` URLs and files in the workspace unless `Ui::allow_remote_media()` is set. `openUrl` opens only http and https links, and sub-agents never draw. Two trace events, `ui_render` and `ui_action`, record what was drawn and answered, never the content.
- **A lighter build** leaves agent86UI out: it is the `agent86ui` feature, on by default.

[docs/agent86ui.md](https://github.com/Maetek-Technologies/agent86/blob/main/docs/agent86ui.md) covers embedding it and what a renderer must do itself (draw surfaces distinctly from its own UI, and show a link before opening it). [ADR 0005](https://github.com/Maetek-Technologies/agent86/blob/main/docs/adr/0005-agent86ui-a2ui.md) records the design and every decision made while building it.

## The `agent86-ui` crate

`agent86-ui` is A2UI 1.0 for Rust, with no other agent86 dependency:

- typed messages in both directions;
- catalogs, checked against the specification's rules;
- a validator that checks a batch all or nothing, against the specification's JSON Schemas (vendored, never fetched) and the rules they cannot express;
- a headless surface runtime a renderer can build on. It resolves every binding, function call, template, and check, writes user input back, and dispatches actions. The basic catalog's functions are implemented, with `en-US` formatting and A2UI's regular-expression dialect and its safety rules.

Its tests replay the specification's own test cases and the shared conformance suites every A2UI SDK runs. The cases left out of those suites are listed in the tests, each with its reason.

## Breaking changes for Rust callers

These types are now `#[non_exhaustive]`, so later releases can add to them without breaking you:

- `TurnEvent`, `BuildError`, and `RunError`: a `match` outside the crate needs a `_` arm.
- `RunResult`: code outside the crate reads the fields it needs, but can no longer build one or destructure it without `..`.

`TurnEvent::Ui`, `BuildError::Ui`, and `RunError::UiAction` are new variants. They exist only with the default `agent86ui` feature.

## The CLI

Nothing changes for CLI users: the interface, `run` and `run --json`, the ACP server, the config files, and the session, trace, and keyring formats are as they were in 1.1.0. agent86UI comes to ACP clients in 1.2.1 and to the terminal interface in 1.2.2.

The `url` dependency is updated to 2.5.9, for RUSTSEC-2026-0592.

The minimum supported Rust version is still 1.94.
