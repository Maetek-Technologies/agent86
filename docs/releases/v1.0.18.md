Specialist sub-agents: named helpers with their own instructions, tools, and model, which the agent or you can call by name. Sub-agents now follow routing and stop when you cancel.

## Specialist sub-agents

- **Named, reusable sub-agents.** A Markdown file with a short frontmatter defines a *specialist*: its instructions, and optionally the tools it may use, a stricter approval mode, tools that are always asked about, its own model, a step budget, and skills to preload. Put one in `~/.agent86/agents/<name>.md` for yourself, or in a project's `.agent86/agents/<name>.md`. Three ship with agent86: `researcher` (reads files and the web, changes nothing), `reviewer` (reads, and runs commands only after asking you, even in auto mode), and `planner` (reads and writes a plan). A file of your own with the same name replaces a built-in.
- **The agent picks one.** The agent sees the specialists' names and descriptions, and hands work to one with `delegate`'s new `agent` argument. A specialist can only do less than the agent that called it, never more, including when it delegates further.
- **Or you do.** `/agent <name> <task>` runs a specialist right away, with no main-agent call in between (`/agent --with-context ...` hands it a summary of the conversation so far). `/agents` lists them, and `/agents <name>` shows one in full. Typing `#name` in a prompt asks the agent to delegate to that specialist; the `#` menu completes the names. `agent86 run --agent <name> "<goal>"` makes a specialist the main agent of a one-shot run. All of this works in the terminal and in editors.
- **Project specialists are checked first.** A specialist that comes with a repository is shown to you in full and approved before it first runs. agent86 remembers the approval for that exact file and asks again if the file changes. With nobody there to ask (a script, CI), it is refused unless you pass `--trust-project`. In an editor you get one option, *Allow this version of <name>*.
- **Several at once.** When the agent calls several specialists together, they run at the same time (up to three; `[agents] max_parallel` changes that, up to eight). Their questions to you come one at a time, and together they stay within the turn's cost limit.
- **Work in a separate copy.** A specialist with `isolation: worktree` (or a delegation with `isolate: true`) works in a git worktree made from your last commit, not in your files. Its answer includes the diff of what it changed, and nothing is applied for you. A worktree with changes is kept, and its location is reported; one without changes is removed.
- **In editors,** each delegation is one tool call card. It is named for the specialist and its task, lists the specialist's calls while it runs, and ends with its answer. A question from a specialist says which one is asking.

See [docs/subagents.md](https://github.com/Maetek-Technologies/agent86/blob/main/docs/subagents.md) for the file format and every option.

## Fixes

- **Sub-agents follow routing.** With triage routing on (`[model] router = "triage"`), a sub-agent ran on your default model while its trace named the routed one. It now runs on the model the turn was routed to.
- **Cancel stops sub-agents.** Escape, Ctrl+C, or an editor's stop now stops a running sub-agent at its next safe point too, instead of letting it finish its work first. In an editor, closing the connection also stops the turn, and no new question is sent after you cancel.
- **Unique tool call ids in editors.** Models that reuse call ids from one turn to the next (Ollama's `ollama-0`, `ollama-1`, ...) could make an editor confuse two calls. Each call now gets an id of its own.
