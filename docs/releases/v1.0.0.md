The first release of agent86-rs, a Rust port of [agent86](https://github.com/Maetek-Technologies/agent-86) that behaves like the Python version and ships as one native binary. You don't need Python to run it. You only need a Python interpreter for the `python_exec` tool and for MCP servers written in Python.

agent86-rs reads and writes the same files as Python agent86 1.0.0: `~/.agent86/config.toml`, the session and memory database, the trace log, the prompt history, and keys stored in the OS keyring. You can switch between the two on the same machine, and a session started in one can be resumed in the other.

## Install

Download the archive for your platform, extract it, and put `agent86` (or `agent86.exe`) on your `PATH`.

| Platform | Archive |
|---|---|
| Linux x86_64 (glibc) | `agent86-v1.0.0-x86_64-unknown-linux-gnu.tar.gz` |
| macOS Apple silicon | `agent86-v1.0.0-aarch64-apple-darwin.tar.gz` |
| macOS Intel | `agent86-v1.0.0-x86_64-apple-darwin.tar.gz` |
| Windows x86_64 | `agent86-v1.0.0-x86_64-pc-windows-msvc.zip` |

Each archive has a `.sha256` file next to it. The binaries are not signed:

- **macOS:** clear the quarantine flag once with `xattr -d com.apple.quarantine agent86`.
- **Windows:** SmartScreen may ask you to confirm the first time you run it.

To build from source instead, use Rust 1.88 or newer: `cargo install --git https://github.com/tdfleming/agent-86-rs --tag v1.0.0`.

## Getting started

```bash
agent86 keys set openrouter                         # stored in the OS keyring, input hidden
agent86 --model openrouter:openai/gpt-4o-mini run "Summarize this repository"
agent86 --model openrouter:openai/gpt-4o-mini       # the interactive interface
```

`agent86 models` lists the configured providers and where each one's key comes from. In the interface, `/config model` sets up a provider, its key, and a model.

## What's included

Everything you can reach from Python agent86's CLI and interactive interfaces is here:

- **Providers:** OpenAI-compatible endpoints (OpenAI, OpenRouter, Groq, and any `base_url`), Anthropic, Ollama, and llama.cpp or LM Studio. Responses stream, failed requests are retried as in Python, and estimated costs use Python's price table.
- **The agent:**
  - Python's ReAct loop with its system prompt and circuit breakers, with long conversations fitted to the model's context window by compaction.
  - Tools: `read_file`, `write_file`, `edit_file`, `list_dir`, `run_command`, `python_exec`, and `web_fetch`.
  - Approvals: `ask`, `auto`, or `deny`.
- **Safety:**
  - Ingress, egress, and observation guardrails.
  - A sandbox for commands: a scrubbed environment, timeouts that kill the whole process tree, and optionally Docker.
  - A workspace jail for file access, and SSRF protection on every `web_fetch` redirect.
- **One-shot runs:** `run` and `run --json`, with Python's output, exit codes, and JSON fields.
- **The interactive interface:** drawn inline in your terminal, with:
  - Python's slash commands and `@file` mentions, and prompt history shared with Python.
  - Pickers for the model, approval mode, and session, and panels for approvals.
  - `/config model` and `/config mcp` for managing providers, keys, and MCP servers.
  - Markdown replies and coloured diffs.
  - `--plain` for Python's plain loop.
- **Sessions and memory:**
  - Sessions are saved and can be resumed with `run --session` or `--resume`.
  - Earlier episodes are recalled into similar later tasks, and the agent can `remember` and `recall` facts.
  - Text is embedded locally with `all-MiniLM-L6-v2` from the shared Hugging Face cache.
  - `agent86 memory` inspects and trims the store.
- **MCP:** servers over stdio, streamable HTTP, and SSE, with reconnects and `list_changed` handled, and resource, prompt, and completion tools.
- **Skills and sub-agents:** `SKILL.md` folders with `allowed-tools`, and `delegate`.
- **Triage routing:** with `[model] router = "triage"`, each turn goes to a cheap or a frontier model depending on the task.
- **Observability:**
  - A redacted flight recorder, read with `agent86 trace show|export`.
  - OpenTelemetry spans exported over OTLP/HTTP or to the console.

## Beyond Python

- **Turn limits you can change at runtime:**
  - `/limits` in the interface, and `run --max-steps`, `--max-output-tokens`, and `--max-agent-steps`.
  - When a turn or a sub-agent reaches a limit, the interface offers to raise it and carry on.
- **`agent86 keys set|delete`:** stores provider keys from the command line.

## Known differences

[docs/PROJECT_PLAN.md](https://github.com/tdfleming/agent-86-rs/blob/v1.0.0/docs/PROJECT_PLAN.md) lists every known difference from Python. The ones you're most likely to notice:

- **OpenTelemetry export** uses OTLP over HTTP with JSON (`localhost:4318`), not gRPC.
- **Help and tables** are plain aligned text rather than Rich formatting.
- **The interactive interface** is drawn inline rather than full-screen.
- **Usage pricing** is looked up under the full `provider:model` ref, so a `[pricing.models]` rate keyed by the ref takes effect. In Python such a rate marks the model as priced but is never applied.
