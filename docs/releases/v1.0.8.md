`/update now` works on Windows under npm.

## What's fixed

- **`/update now` on Windows:** Windows will not remove a directory holding a running program, and npm (under Volta, for one) replaces the whole package directory. 1.0.7 renamed the running binary inside that directory, so the install failed and could leave the launcher with no binary. Now the running binary is first moved to the temporary directory, put back if the install fails, and deleted at a later start. If it cannot be moved, `/update now` says to quit agent86 and gives the command to run.

**On 1.0.7 or earlier on Windows?** Update from a terminal, not with `/update now`, since the fix is in the new version:

```sh
npm install -g agent86@latest
```

From 1.0.8 on, `/update now` works. Everything else behaves as in 1.0.7.

## Install

```sh
npm install -g agent86
```

Or download the archive for your platform, extract it, and put `agent86` (or `agent86.exe`) on your `PATH`.

| Platform | Archive |
|---|---|
| Linux x86_64 (glibc 2.35+) | `agent86-v1.0.8-x86_64-unknown-linux-gnu.tar.gz` |
| Linux ARM64, including Raspberry Pi (glibc 2.35+) | `agent86-v1.0.8-aarch64-unknown-linux-gnu.tar.gz` |
| macOS Apple silicon | `agent86-v1.0.8-aarch64-apple-darwin.tar.gz` |
| macOS Intel | `agent86-v1.0.8-x86_64-apple-darwin.tar.gz` |
| Windows x86_64 | `agent86-v1.0.8-x86_64-pc-windows-msvc.zip` |

Each archive has a `.sha256` file next to it. The binaries are not signed:

- **macOS:** clear the quarantine flag once with `xattr -d com.apple.quarantine agent86`.
- **Windows:** SmartScreen may ask you to confirm the first time you run it.
- **Raspberry Pi:** a headless Pi usually has no Secret Service, so `agent86 keys set` may fail there. Put the key in the provider's environment variable instead (for example `OPENROUTER_API_KEY`).

To build from source instead, use Rust 1.88 or newer: `cargo install --git https://github.com/Maetek-Technologies/agent86 --tag v1.0.8`.
