agent86 can now be driven from your editor.

## Use agent86 from an editor

`agent86 acp` makes agent86 an agent for editors that speak the [Agent Client Protocol](https://agentclientprotocol.com): Zed, the JetBrains IDEs, and many VS Code, Neovim, and Emacs integrations, as well as terminals such as Microsoft's Intelligent Terminal. Point the editor at `agent86` with the argument `acp`. [docs/ACP.md](https://github.com/Maetek-Technologies/agent86/blob/main/docs/ACP.md) has the setup and what to expect.

Each editor thread is an ordinary agent86 session, saved in the same database, so you can continue one at a terminal with `agent86 --resume <id>`, and the reverse.

- **The conversation.** The reply and a thinking model's reasoning stream in as they are written, and every tool call shows with its arguments and result.
- **Approvals in the editor.** Before anything that changes something, the editor asks you, with the diff or the command in front of you. Only *Allow once* lets it run; rejecting, cancelling, or closing the prompt declines, and the model is told. Your approval mode (`ask`, `auto`, `deny`) applies as usual.
- **Stop.** Cancelling in the editor stops the turn at the next safe point, as Escape does in the terminal.
- **Saved threads.** The editor's session list shows your agent86 sessions, and a saved thread can be reopened.
- **Pickers.** The approval mode and the model can be changed from the editor's selectors. The model list starts with the models your config names, and fills in with each provider's own list (OpenRouter, Anthropic, Ollama, and any OpenAI-compatible server you have a key for) as it arrives. `AGENT86_ACP_MODEL_LISTS=off` turns that off.
- **Slash commands.** `/mode`, `/model`, `/thinking`, `/toolview`, `/resume`, `/secret`, `/cost`, and `/tools`, answered without using the model.
- **The editor's own servers and files.** MCP servers configured in the editor are started for the thread. If the editor offers it, `read_file`, `write_file`, and `edit_file` go through the editor, so the model sees your unsaved changes and the approval shows the change from what is on your screen.
- **Secrets.** A secret you enter at a terminal in the project and choose to remember is loaded into that project's editor threads, and the model sees only its name. There is no secret prompt in an editor: the protocol forbids asking for one, and anything typed into the editor stays in its history. `AGENT86_ACP_SECRETS=off` stops editor threads reading the keyring.

## Things to know

- **How well it has been tried.** It has been used in Microsoft's Intelligent Terminal on Windows, and every message it exchanges in the test suite was checked against the protocol's published schema. It has not yet been tried in Zed, the JetBrains IDEs, or the others. If an editor behaves differently from what [docs/ACP.md](https://github.com/Maetek-Technologies/agent86/blob/main/docs/ACP.md) describes, please [open an issue](https://github.com/Maetek-Technologies/agent86/issues).
- **Project settings need trusting first.** An editor can't be asked the trust question, so a project file's riskier settings (MCP servers, providers, approval changes) are ignored until you have trusted the project once at a terminal, or add `--trust-project` before `acp`.
- **Settings come from where the editor starts agent86**, normally the project folder.
- **A new file.** agent86 keeps each editor session's folder in `~/.agent86/acp-sessions.json`, because the shared session database has no place for it.
- **Not built:** the editor's own terminals, remembered "always allow" choices, and images or audio in a prompt.

Nothing changes for the terminal interface, `run`, or sessions you already have.

## Install

```sh
npm install -g agent86
```

Or download the archive for your platform, extract it, and put `agent86` (or `agent86.exe`) on your `PATH`.
