You can now run a skill yourself, instead of waiting for the model to pick it.

## Run a skill directly

- **`/<skill-name> [task]`** runs that skill now, with an optional task: for example `/release-notes for 1.0.16`. **`/skill <name> [task]`** does the same for any skill, including one whose name is taken by a built-in command (a skill called `cost` is run with `/skill cost`, and `/cost` stays the built-in).
- **Everywhere.** It works in the interactive interface, the plain loop, and editors over ACP, and `agent86 run --skill <name> <goal>` does the same for one-shot runs. An unknown skill is refused before the model is called.
- **Listed where commands are.** Skills show in the `/` menu and in `/help`, editors list them with their other commands, and `/skills` (now in editors too) says how to run each one.
- **What happens.** The skill's instructions are sent with your task, and its `allowed-tools` apply from the first step, ending with the turn as before. The rest is an ordinary turn: approvals, guardrails, secrets, the session, and `/cost` work as usual.
- **Names.** A skill gets a command of its own only when its name is plain letters, digits, `-`, and `_`. Others can still be run with `/skill <name>` (if the name has no space) or chosen by the model.

## Fixes

- **`/cost` in editors.** For a model on an OpenAI-compatible provider, such as OpenRouter, `/cost` in an editor said `cost n/a (unpriced model)` even when the model had a price. It now shows the same cost as the terminal.
- **SQLite.** The bundled SQLite is updated (`rusqlite` 0.41) for RUSTSEC-2026-0459: older versions could return uninitialized memory when a database was opened next to a `-wal` file of a different page size.
