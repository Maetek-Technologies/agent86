Clients built on agent86 can now take a secret from their user in their own masked entry and hand it straight to agent86, instead of sending the user to a terminal. As everywhere else, the model only ever sees the secret's name.

## Secrets from clients

- **Hand a secret over.** A client such as agent86-web can set a secret for an open session, list the names held, and forget one, through three new ACP extension requests. It is the terminal's `/secret NAME`: the model uses the secret as `$NAME` in commands and `${secret:NAME}` in files, and anything that would show the value (a file it reads, its own reply, the saved session) shows `${secret:NAME}` instead.
- **Remember it for the project.** Asked to, agent86 keeps the secret in the OS keyring, in the same place as one remembered at the terminal, so later sessions in that folder, in the terminal or in a client, have it too. Setting a remembered secret again without remembering it takes it out of the keyring. With no keyring available, the secret is kept for the session and the client is told so.
- **When the agent asks.** If a client says it has its own masked entry, the model can ask for a secret it needs (`request_secret`), and the client prompts its user for it. A decline, a cancelled turn, or anything the client cannot answer is a refusal, and the model is told.
- **Never repeated back.** The value travels only over the local connection between the client and agent86. No reply, error message, or log line holds it.

Editors that have no masked entry, such as Zed, work as before: secrets come from the terminal (`/secret NAME`, remembered for the project), and `request_secret` is not offered.

## For client authors

- `initialize` now lists `agentCapabilities._meta["com.maetek.agent86/secrets"] = {"version": 1}`.
- `_com.maetek.agent86/secret/set` (`sessionId`, `name`, `value`, `remember`), `_com.maetek.agent86/secret/list`, and `_com.maetek.agent86/secret/forget` are open to any client.
- A client that adds `"com.maetek.agent86/secrets": true` to its own `clientCapabilities._meta` promises to draw a masked entry and to keep what is typed there out of its thread, history, and logs. Only such a client is sent `_com.maetek.agent86/secret/request` when the model calls `request_secret`, and answers with `{"outcome": "entered", "value": ..., "remember": ...}` or `{"outcome": "declined"}`.
- The format is described in [the ACP guide](https://github.com/Maetek-Technologies/agent86/blob/main/docs/ACP.md#agent86s-secrets-an-extension).

`agent86 run`, the terminal interface, and other clients behave as before, apart from the new key in `initialize`.
