agent86 now runs on Google's Gemini models, on vLLM servers, and on LM Studio, each with its own provider, and `/config model` can add a vLLM or LM Studio server anywhere on your network without editing the config file.

## Google (Gemini)

- **`--model google:<model>`.** For example `google:gemini-3.8-flash`, or `google:gemini-3.1-flash-lite` for the cheapest current model that uses tools. The key comes from `GEMINI_API_KEY` or `agent86 keys set google`, and is sent only in a request header, never in the URL.
- **Tools work.** Gemini 3 and 4 attach a "thought signature" to each step's tool calls and refuse the next request without it. agent86 sends it back as Gemini requires, which Gemini's OpenAI-compatible endpoint cannot do. A tool whose name Gemini does not accept (an MCP tool starting with a digit, say) is renamed for Gemini and mapped back.
- **Google keeps no copy.** Every request asks Google not to store it. Since October 2026, new paid projects otherwise keep requests in AI Studio's logs for 55 days, and a request holds every file the agent read. `[providers.google] store = true` turns storage back on.
- **Thinking, models, and prices.** Gemini's thought summaries are shown apart from the answer. `/model` lists Google's chat models, the context window comes from Google, and current Gemini models have built-in prices, including their cheaper cached input.
- **When Google stops a reply itself** (a safety block, for example), agent86 says `[google stopped the reply: SAFETY]` once and does not ask the model again. A project whose prepaid credits ran out gets told so instead of retried.
- agent86 sends Gemini no temperature: Google says its newest models ignore it and its earlier Gemini 3 models should keep the default.

## vLLM

- **`--model vllm:<model>`** reaches a vLLM server at `localhost:8000`. A key is sent when you set one (`VLLM_API_KEY`, or `agent86 keys set vllm`) and is not needed otherwise.
- **The server's own context window** (`max_model_len`) is used, and vLLM is free in cost totals.
- **Errors that say what to do.** vLLM's errors for a server started without `--enable-auto-tool-choice` and `--tool-call-parser`, for a conversation past its context length, for an unknown model, and for a missing key keep vLLM's text and add the fix. An error vLLM sends in the middle of a reply is now shown instead of ending in an empty answer.

## LM Studio

- **`--model lmstudio:<model>`** reaches LM Studio's server at `localhost:1234`. `/model` lists every chat model you have downloaded and marks the loaded ones and those not trained for tool use.
- **The length the model was loaded with.** LM Studio loads a model with a context length you choose, often far below its maximum, and refuses requests past it. agent86 uses that loaded length, and learns it again once the first request has loaded the model, so it compacts the conversation before LM Studio would refuse it.
- **An API token**, if you turned on LM Studio's "Require Authentication", is sent when set (`LM_API_TOKEN`, or `agent86 keys set lmstudio`).
- A config that reaches LM Studio through `llamacpp` keeps working. Switch to `lmstudio` for the model list and the window.

## Servers anywhere on your network

- **`/config model` → "add a vLLM or LM Studio server".** Give the kind, a name, the address, and a key only if the server needs one. agent86 asks the server for its models with no key first and asks you for one only if the server refuses, tests a real reply, and saves the server to your own config file, never the project's.
- **Safe with keys.** A key typed there goes into the OS keyring only after the test passes. Changing a server's address never sends its stored key to the new host unless you confirm it or type a new key, and a key that would cross the network over plain `http://` gets a warning.
- **By hand**, any `[providers.<name>]` section with `adapter = "vllm"` or `adapter = "lmstudio"` is such a server.

## Also

- agent86 no longer depends on `chrono`, which RustSec marked unmaintained; the times it prints are unchanged.

Google was checked against the live API, including tool calls on Gemini 3.1 Flash-Lite and Gemini 4 Hydrogen. vLLM and LM Studio were checked against recorded responses in their documented formats, not yet against live servers.
