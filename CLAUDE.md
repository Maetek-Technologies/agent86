# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A compatibility-first Rust port of [agent86](https://github.com/Maetek-Technologies/agent-86), a Python agentic CLI harness. **The Python implementation is the behavioral oracle**: the Rust code must reproduce its observable behavior (CLI output streams, exit codes, `run --json` fields, TOML config semantics, provider streaming/tool-call behavior, approvals, session/trace formats, error degradation), not its internal structure.

The CLI can run one text-only turn against any OpenAI-compatible provider (`agent86 --model provider:model run [--json] <goal>`), as an agent over the current directory: Python's system prompt, the ReAct loop, and `read_file`, `write_file`, `edit_file`, and `list_dir`, with side-effecting calls passing through the approval gate. Python's ingress, egress, and observation guardrails apply. `run_command` and `python_exec` run under the sandbox executor, and `web_fetch` is guarded against SSRF. Each run is a session saved in Python's SQLite memory database and resumable with `run --session`; finished turns are recorded as episodes and recalled into similar later tasks, and the agent can `remember` and `recall` facts (`agent86 memory` inspects the store), embedded with Python's default `all-MiniLM-L6-v2` run on candle from the shared Hugging Face cache. The flight recorder logs it to `~/.agent86/traces/trace.jsonl`. Configured MCP servers (stdio, streamable HTTP, or SSE) are started for each run and their tools registered next to the built-ins, and kept in step with drops, reconnects, and `list_changed` while the run goes on. `agent86` with no subcommand opens the interactive interface: Python's REPL (its slash commands, `@file` mentions, and prompt history) rendered inline in Claude Code's style, with an approval panel, a spinner, a live status line, and Escape or Ctrl+C to cancel a turn at its next safe point. `/config model` and `/config mcp` manage providers, keys, models, and MCP servers, writing config back with comments kept. `--plain`, `AGENT86_PLAIN`, or piped input gives Python's plain loop. `docs/PROJECT_PLAN.md` is the source of truth for current status, the next steps, the staged roadmap, known differences from Python, and the credential policy. Read it before starting feature work, and update it (plus the README status/roadmap) when a stage lands. Keep both honest about what is and is not implemented.

## Commands

```bash
cargo test --all-targets                     # all tests
cargo test --test compatibility              # just the compatibility suite
cargo test --test openai_provider            # provider tests against the local mock server
cargo test --test cli_run                    # end-to-end tests that run the agent86 binary
cargo test <test_name_substring>             # single test, e.g. cargo test model_refs_split
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings    # warnings are errors
cargo run -- --help
```

All three checks (test, fmt, clippy `-D warnings`) must pass. `unsafe_code` is forbidden at the crate level. MSRV is Rust 1.88 (`rust-version` in Cargo.toml, set by `tokio`/`reqwest` and their URL dependencies); avoid newer language/std features, and check a new dependency's `rust-version` before adding it. `.cargo/config.toml` makes the resolver prefer MSRV-compatible versions, but platform-specific dependencies (for example the Linux keyring stack) only build in CI, so watch the Linux and macOS MSRV jobs. Raising the MSRV is a deliberate change: update Cargo.toml and the CI matrix together.

CI (`.github/workflows/ci.yml`) runs tests on Linux, macOS, and Windows against both stable and the MSRV, with fmt and clippy on stable. Windows builds need the Visual Studio Build Tools C++ workload for `link.exe`.

## Architecture

- `src/types.rs`: the provider-neutral vocabulary everything else will build on: `Role`, `AgentPhase`, `ApprovalMode`, `StopReason`, `ModelRef`, `ToolSpec`/`ToolCall`/`ToolResult`, `Message`, `CompletionRequest`/`Completion`/`CompletionDelta`, `Step`, `Usage` (implements `Add` for accumulation).
- `src/provider/`: the model layer, ported from Python's `agent86/cognitive/`.
  - `mod.rs`: the object-safe `Provider` trait, `ProviderError`, and `provider_for_ref`, the factory. `anthropic` and `ollama` get their own adapters; `llamacpp` is the OpenAI-compatible adapter under its own name, keyless, with a local default URL; any other provider section with a `base_url` becomes the OpenAI-compatible adapter. Providers implement only `stream()`, which returns a boxed stream of `CompletionDelta`s whose last item has `done = true` plus the full `Completion`. `complete()` is derived by collecting that stream, so streamed and non-streamed text always agree. `ProviderError` messages mirror the Python wording and are stored already redacted.
  - `openai.rs`: the OpenAI-compatible SSE provider (OpenAI, OpenRouter, Groq, local servers). The stream is a hand-written state machine (`StreamState`) driven by `futures_util::stream::unfold`; dropping the stream drops the HTTP response, which is how cancellation works. Per-attempt accumulators live in `TurnState` and reset on every retry.
  - `anthropic.rs`: the Anthropic provider on the Messages API event stream. Python goes through the `anthropic` SDK, so the SDK's retry rules, fixed timeouts, and error text (the body printed as a Python dict, via `python_repr_value`) are part of the contract, alongside the adapter's prompt-cache markers and sampling fallback. Failures the SDK leaves unconverted get the wording Python's loop gives them. Tests use `tests/fixtures/anthropic/*.sse` with the mock server.
  - `ollama.rs`: the Ollama provider: NDJSON from `/api/chat`, the same `unfold` state machine and retry rules as `openai.rs`, zero-cost usage, and Python's messages as preformatted `ProviderError::Message`s. Tests use `tests/fixtures/ollama/*.ndjson` with the mock server.
  - `retry.rs`: retryable statuses, `Retry-After`, and jittered backoff. A retry is never allowed once a text delta has been emitted, because the caller already saw that text.
  - `capabilities.rs`: models that reject sampling parameters, and `context_window_with` (Python's `context_window_for`) for the status line; `remote_windows.rs` asks OpenRouter for a model's window, memoized and cached for 24 hours in Python's cache file. `context_window_for` is the variant that never touches the network.
  - `catalog.rs`: live model lists in Python's three shapes (OpenAI-compatible, Anthropic, Ollama), blocking on a thread of their own; every failure is a `CatalogUnavailable` with Python's message. `prefix_catalog_refs` and `catalog_has_ref` are the exact-prefix and exact-match rules the `/model` paths share.
- `src/secrets.rs`: `redact()`, ported from Python's `secrets.py`. Run every response body or transport error through it before it reaches a `ProviderError`. Also `resolve_api_key()`: the `api_key_env` variable, then a `SecretStore` (`OsKeyring` in production; tests pass a fake or `NoSecretStore` through `provider_for_ref_with_store`, and must never touch the real keyring). On Windows `resolve_windows_credential` reproduces the Python `keyring` layout (`agent86`, then `<account>@agent86`); keep it that way so keys Python stored stay readable.
- `src/pricing.rs`: `PriceTable`, ported from `pricing.py` (built-in rates, local providers at zero, dated-snapshot matching, cache rates, `[pricing.models]` overrides). Python keeps overrides in a module global; here the table is passed to the provider with `with_pricing`, and usage is priced under the full `provider:model` ref (a deliberate fix, see the plan). Unknown models cost `0.0` but must display as `cost n/a`, so ask `is_priced` before showing a dollar figure.
- `src/pyjson.rs`: `python_float`, a `serialize_with` that writes floats exactly as Python's `json.dumps` does (`1.44e-05`); use it on every `f64` field that reaches `run --json`. `python_json_dumps` reproduces `json.dumps` text (separators, key order, `ensure_ascii`), for tool previews and the arguments sent back to the model. `serde_json` is built with `preserve_order`, so maps keep insertion order everywhere.
- `src/prompt.rs`: the system prompt. `BASE_IDENTITY` must stay byte-identical to Python's `_BASE_IDENTITY`; `tests/system_prompt.rs` compares it with `tests/fixtures/prompt/base_identity.txt`, which was extracted from the Python source with `ast` (parsed, never executed). Re-extract it the same way when the reference changes.
- `src/keys.rs`: `agent86 keys set|delete`. All checks (known provider with `api_key_env`, non-empty single paste) run before the keyring is written, so CLI tests cover only refusals; never add a test that stores a real key. Hidden input uses `rpassword`, except under MSYS (`MSYSTEM` set, i.e. Git Bash), where console prompts cannot read input and `stty -echo` is used instead. On Windows the store leaves `UserName` empty for credentials created under an explicit target, so `CredentialVault::write` must set it explicitly; `tests/os_keyring.rs` has an opt-in live round trip that catches this.
- `src/tools/`: the tool layer. `Tool` (`execute` returns `Result<ToolResult, ToolError>`; the provided `run` turns failures into `ok = false` results with Python's messages: `Invalid arguments for '<tool>': <field>: <msg>` or `<PythonException>: <msg>`). `Arguments` reproduces pydantic validation messages. `SandboxPolicy::resolve_within` is the workspace jail; every path a tool touches must go through it. `parameters()` must equal what pydantic generates for the Python `Args` model: `tests/fixtures/tools/schemas.json` was produced by a local script mirroring those models (not by running the reference repo), so regenerate it the same way when adding a tool.
- `src/approval.rs`: `ApprovalGate` (`auto`/`ask`/`deny`; the mode sits behind a lock, read with `mode()` and changed with `set_mode()`, so the interface can switch it mid-turn) and the terminal prompt. `ApprovalPreview` carries the tool's `preview_lexer`, as Python's does. The prompt is only installed when stdin is a terminal; without one, `ask` declines, and that is what makes piped and CI runs safe. Approvals are always settled on the loop's thread before any tool runs (`Harness::resolve_call`), never inside the parallel read path.
- `src/guardrails.rs`: Python's scanner regexes, verbatim. `tests/guardrails.rs` compares the pattern strings with `tests/fixtures/guardrails/scanners.json` (extracted from the Python source with `ast`) and the scan and redaction results with CPython's `re`; keep both checks passing when patterns change. In `egress = "redact"` mode the loop must never emit unredacted model text, so streaming is buffered per step.
- `src/tools/sandbox.rs`: the executors. `run_subprocess` must keep three properties: the scrubbed environment (`env_clear` plus `scrubbed_env`, never inheriting), a deadline covering both process exit and pipe EOF, and a process-tree kill on timeout. Child working directories go through `plain_path`, because `cmd.exe` cannot use a `\\?\` path. `tests/exec_tools.rs` runs real processes on every platform.
- `src/tools/web.rs`: `web_fetch`. Every hop must go through `vet_url` before a connection, and the client must be pinned to the vetted addresses (`resolve_to_addrs`); never enable automatic redirects. `block_reason` mirrors Python 3.12 `ipaddress` and is checked against `tests/fixtures/web/golden.json`. Tools run synchronously inside the harness runtime, so the fetch runs on a scoped thread with its own runtime.
- `src/difflib.rs`: a port of CPython's `SequenceMatcher` and `unified_diff`, plus Python's `splitlines`. File-tool diffs must come from here, not a diff crate, because other algorithms group hunks differently. `tests/fixtures/tools/write_tools.json` holds CPython-generated diffs.
- `src/config.rs`: layered TOML config: built-in defaults (a TOML string), the user file, the project file, `AGENT86_MODEL`, then `--model`, deep-merged as `toml::Table`s before deserializing. Unknown sections and keys are ignored, as Python's pydantic models allow. `ConfigPaths` and `Overrides` are explicit parameters so tests never touch the real home directory. Providers keep config order (an `IndexMap`), as Python lists them.
- `src/config_writer.rs`: comment-preserving write-back with `toml_edit`, ported from `config_writer.py`. `plan_edit` computes the text and the diff without touching the disk; `apply_edit` writes atomically and reloads from the files and the environment (not the CLI flags, as Python's `load_config()`). The secret guard refuses secret-shaped leaf keys unless the value is a pure `${VAR}` reference; never weaken it. A change with no value removes the path; comments above a removed table move to the next table, as `tomlkit` keeps them.
- `src/agent.rs`: the ReAct loop (`Harness::run_turn`) and `CircuitBreaker`. Everything a turn streams, including `[tool] ...` notices, goes through one `emit` closure, so the text output and `run --json`'s `output` stay identical, as in Python. Tool results must be pushed back in call order, even when calls run in parallel. `run_turn_events` reports `TurnEvent`s (text, tool call, tool result), each carrying the text the other entry points stream, so the interface never parses `[tool] ...` lines. `CancelToken` is Python's `cancel()`: the turn clears it on entry and checks it only at Python's safe points (before a model call, while streaming, between tool calls), so a running tool always finishes and every tool call in the history gets an answer. Every request is fitted to `context_budget` (the harness's `context_window`, set by `setup::model_context_window` and again on `/model`), and `compact_if_needed` runs before each model call; `src/memory/working.rs` is the port of Python's `working.py` (token estimate, budget, `fit`, `compaction_cut`, the summarizer prompt, extracted with `ast` into `tests/fixtures/memory/working.json`).
- `src/setup.rs`: `assemble` builds the harness (provider, jailed tool context, executor, session store, MCP) for both `run` and the REPL; keep the two paths going through it. `open_memory` builds the embedder and the store (or Python's degradation note), and retention runs there at startup.
- `src/repl.rs`: the plain REPL and the slash-command registry (`COMMANDS`, ported from `tui/commands.py`, which both Python surfaces share). Commands return `Text` (styled spans) and the loop prints it, so the registry stays testable without a terminal. Python's `needs_choice` and `clears_transcript` are on the entry and the result; the interface acts on them, never on a command's name. `model_switches` counts successful `/model` switches, which is how the interface tells a switch from a refusal. Stdin is read by a helper thread only on demand, so the approval prompt can read stdin during a turn; a signal thread turns Ctrl+C into a cancel. `start_repl` builds the session both surfaces run on, and `plain_loop` runs Python's loop on it. `history.rs` (the prompt history file) and `mentions.rs` (`@path` expansion, jailed through `resolve_within`) are shared by both surfaces.
- `src/ui/`: the interactive interface ([ADR 0001](docs/adr/0001-inline-terminal-interface.md), design and remaining slices in `docs/INTERFACE.md`), Python's full-screen app reworked to render inline:
  - `mod.rs`: surface selection, the terminal guard (restores the terminal on drop and on panic), the event pump, and the turn worker. A turn runs on a scoped thread that borrows the harness and the state while the pump keeps drawing; approvals reach the panel over the event channel, and a dropped reply declines.
  - `app.rs`: the state machine, with no terminal access, so tests drive it with key and turn events.
  - `screen.rs`: the Ink-style renderer, which erases the rows it drew last, prints finished lines into scrollback, and redraws the live region. Every live row must fit the width, so the row count stays exact.
  - `text.rs`: lines, wrapping in terminal cells, and `sanitize`, which every piece of model, tool, or server text goes through before it is drawn.
  - `status.rs`: Python's status line and its shedding order.
  - `input.rs`: the prompt editor with Python's history rules.
  - `markdown.rs`: replies as Markdown (`pulldown-cmark`), block by block. `commit_point` decides how much of a streaming reply is complete blocks (never inside a code fence or a loose list); only complete blocks reach scrollback, because they can't be re-rendered there. `diff.rs` colours an approval's detail by the tool's `preview_lexer`.
  - `entries.rs`: everything printed, kept as entries (lines as printed, tool calls with full arguments and result) for the Ctrl+O transcript view, which `App::view_page` draws on the alternate screen; `App::commit` and `commit_tool` keep scrollback and entries in step.
  - `menu.rs`: the `/` command menu and `@` path completion under the input box (`complete_mentions` is in `src/mentions.rs`, jailed to the workspace). `picker.rs`: the mode, model, session, provider, and catalog pickers; a choice comes back as `Request::Picked` and is dispatched as the command it stands for, or drives the `/config model` chain.
  - `panels.rs` and `manage.rs`: the `/config model` chain (provider list, key entry, catalog picker, connection test, save diff) and the session's catalog cache. Panels answer with a `Request`; slow work (catalog fetches, the test) runs on worker threads and comes back as `UiEvent`s, and a catalog waits in `App`'s deferred queue until no turn runs and no panel is open. A typed key is never drawn and reaches the keyring only after the test passes or the user saves anyway.
  - `mcp_config.rs`, `mcp_panels.rs`, and `manage_mcp.rs`: the `/config mcp` chain (server list, form, `${VAR}` prompts through the key entry, MCP test, save, mount or unmount). `mcp_config.rs` holds the pure helpers (both README JSON shapes, the manual fields, a `shlex` port checked against CPython, and the save's changes, one key per env or header value so the secret guard sees each). A key entry or save panel carries its purpose, so one panel type serves both chains. The test's worker gets every `${VAR}` value resolved beforehand (the keyring is not `Send`), and a test closed early stops the server it started.
- `src/mcp/`: the MCP client. `transport.rs` has the `Router` (routes responses to waiting requests, answers `ping`, passes notifications on, and fires a close handler when the transport ends) and the stdio, streamable HTTP, and SSE transports; the HTTP ones run on their own thread and runtime, fed by a channel, so sending never needs an async context. `mod.rs` has `McpManager`: one supervisor thread per server owns reconnects; `Slot` holds each server's state, session, and tools; every request goes through `Inner::request`, the single source of Python's unavailable and timeout messages. Tools hold a `Weak` back to the manager. `McpTool` defers its schema until first `run`; `CapabilityTool` covers resources, prompts, and completions. `render.rs` is pure rendering. The manager mutates the shared `ToolRegistry` (clones share one lock-guarded list; removal is identity-checked), and `Harness::system_message` rebuilds the MCP prompt section per request. `start_server` (start one server without registering it, with typed `${VAR}` overrides and the test's budget), `mount`, and `remove_server` are the runtime API `/config mcp` uses; `Repl::ensure_mcp` makes an empty manager when the session started with none. Tests drive the stdlib-only server in `tests/fixtures/mcp/server.py` (stdio, `http`, and `sse` modes), so they need `python3` or `python` on PATH and skip when neither runs.
- `src/observability.rs`: the flight recorder, its redaction, trace reading, and the OTLP reconstruction. Every event goes through `redact_event` before it is written; new events should use Python's kind and field names (see `orchestration/loop.py`), because the trace format is shared. `tests/fixtures/trace/golden.json` pins redaction and the OTLP document to a mirror of Python's code.
- `src/skills.rs`: skill discovery (Python's root order and precedence, home passed explicitly so tests never read the real one), `SKILL.md` parsing with Python's built-in frontmatter parser (not PyYAML), and `Skill` (instructions read once, bundled resources). `src/tools/skills.rs` is `use_skill`; `ToolContext` carries the skills and the active skill (shared by clones, cleared when a turn starts and ends), and `ToolRegistry::dispatch` refuses tools outside its `allowed-tools`. `setup::assemble` adds the skill roots to the jail with `SandboxPolicy::allow`.
- `src/subagent.rs`: sub-agents, as more `impl Harness` methods. `delegate` (`src/tools/delegate.rs`, schema and argument rules only) is intercepted by the harness (`Harness::delegation`) and its sub-agent awaited on the turn's runtime, never inside a tool; this works because `delegate` is not `parallel_safe`, so it always runs in the batch's sequential part, which `execute_batch` runs async. Sub-agent usage comes back with each result and is added to the step, the summary, and the breaker. A sub-agent uses a `ToolContext::fork` (its own active skill). `tests/fixtures/skills/python_strings.json` (the preamble and tool descriptions) is extracted with `ast`.
- `src/router.rs`: triage routing, ported from `orchestration/router.py`. `Harness::route` picks the turn's model after the ingress guardrail; the routed `RoutedModel` (provider, output cap, window) stays current after the turn, as Python's `self.provider` does. Read the model through `Harness::active_provider` (and `active_context_window`, `output_cap`, `Repl::model_ref`), never `harness.provider`, which is only the session's default or pinned model. `/model` calls `Router::pin`. Routes are built by `setup::build_router` from the startup config, as Python's harness keeps its config; tests inject a `ModelBuilder`.
- `src/limits.rs`: turn limits at runtime, beyond Python (record changes as such in the plan): `SessionLimits` on the harness holds the session's overrides of `steps` (`[limits] max_steps`), `agent_steps` (`[agents] max_steps`, clamped under `steps`), and `output` (which replaces whichever cap `max_output_tokens_for` picks, so it always takes effect), behind a lock so a running turn can raise one, plus the `LimitPrompt` hook. Read the effective values through `Harness::max_steps`, `agent_max_steps`, and `output_cap`, never the config fields. Only the interface installs the hook (`src/ui/limits.rs`), as it does the approval prompt; without it a limit ends the turn or the sub-agent as in Python. `/limits` is in the registry, `run --max-steps`/`--max-output-tokens`/`--max-agent-steps` set the same overrides, and `save_changes` writes each one to the setting it replaces. Sub-agents send `output_cap()` (Python sends none, a deliberate fix).
- `src/memory/`: long-term memory, as more `impl SessionStore` methods: episodes (recorded when a turn finishes, recalled into the next similar turn's system message by `recall_note`), facts (`src/tools/memory.rs` has `remember` and `recall`), ranking, `prune`, and `enforce_retention`. `embeddings.rs` has the `Embedder` trait, `build_embedder`, and the hashing embedder, which must stay bit-identical to Python's. `sentence_transformers.rs` runs sentence-transformers BERT models on candle (`float32`, the model's pooling, normalization; the `tokenizers` crate at candle's version, which is Python's); `hub.rs` is the Hugging Face cache in `huggingface_hub`'s layout and the download, and takes an explicit `Hub` so tests never use the real cache or network. `tests/memory_models.rs` checks a tiny random BERT fixture (`tests/fixtures/memory/tiny-st/`, in MiniLM's 2021 layout) against vectors sentence-transformers produced, to 1e-6, and serves downloads from the mock server; `AGENT86_TEST_MINILM=1` also checks the cached real model against `minilm.json`. Regenerate those fixtures with sentence-transformers itself, never with the reference code; vectors are stored as little-endian `float32` and scores are summed with `python_sum` (Python 3.12's compensated `sum`). `tests/fixtures/memory/golden.json` comes from a local mirror script (CPython `hashlib`/`array`, pydantic), with floats as `repr` strings because `serde_json`'s float parsing is not correctly rounded. CLI and REPL tests set `embeddings = "hash:256"` in their isolated home and run with `HF_HUB_OFFLINE=1` and no `HF_*` cache variables, so no test downloads a model or reads the real cache.
- `src/session.rs`: `AgentState` and `SessionStore` (a cloneable handle: clones share one locked connection, so the CLI, the harness, and the memory tools use one store). The database file, schema, and `state_json` are shared with the Python implementation, so keep `AgentState` readable by Python's pydantic models (`tests/fixtures/session/python_state.json` covers the other direction). `Harness::run_turn` works on a `&mut AgentState`; the CLI persists before and after every turn, including failed ones.
- `src/turn.rs`: `RunOutput` (the `run --json` document; field order is the contract, so it is a typed struct), `TurnSummary`, and the stderr summary line.
- `src/main.rs`: the `clap` CLI. As with Typer, `--model`, `--sandbox`, and `--approval` are top-level options and must come before the subcommand. `models` and a bare `config` share `cli_models_tables` with `/models` (which orders the tables differently, as Python's do); a test that lists providers must set every built-in provider's key variable so the real keyring is never read. Errors print `error: ...` plus a hint on stderr and exit 1; usage errors exit 2; ANSI styling only when stderr is a terminal and `NO_COLOR` is unset.
- `tests/compatibility.rs`: integration tests that pin the JSON wire format to the Python vocabulary.
- `tests/openai_provider.rs` with `tests/support/mod.rs`: a scripted HTTP/1.1 mock server (one `Reply` per connection: full status, SSE, truncated, or stalled) plus recorded fixtures in `tests/fixtures/openai/*.sse` (kept LF by `.gitattributes`).
- `tests/cli_run.rs`: runs the real binary against the mock server inside a throwaway workspace whose `HOME`/`USERPROFILE`, working directory, and environment are isolated. Use this pattern for any test of CLI output or exit codes. `tests/repl.rs` does the same for the REPL, with piped stdin (so no banner, colour, or approval prompt).

When porting a module, read the Python source first. It is public at `Maetek-Technologies/agent-86` (`src/agent86/...`); its comments explain why each behavior exists, and those reasons usually belong in the Rust doc comments too.

Conventions encoded in the types that must be preserved:

- Serde JSON is the wire format and must match the Python field names and values exactly. Enums use `rename_all = "snake_case"` (e.g. `end_turn`, `tool_use`). Optional/empty fields use `skip_serializing_if` plus `default` so absent and empty round-trip the same way Python does. `ToolResult.ok` defaults to `true` when missing.
- `ModelRef::parse` splits `provider:model` on the **first** colon only and trims whitespace (`local:model:variant` gives model `model:variant`).
- When a provider returns malformed tool-call JSON, the raw string is kept under `INVALID_TOOL_ARGS_KEY` (`"__invalid_json__"`) in `ToolCall.arguments` rather than failing; read it back with `ToolCall::invalid_arguments()`.

## Working rules for this port

- Shell commands from the Bash tool collapse doubled backslashes, so write source or fixtures containing backslash escapes with the Write or Edit tools, never via heredocs.

- Add behavior only together with tests that make the compatibility contract explicit. Compare observable behavior; don't copy Python implementation details. Design around Rust async ownership and cancellation instead of literally reproducing Python's threads and event loops.
- Work in small vertical slices that follow the roadmap order. Don't broaden features beyond what the Python version does.
- `run --json` must emit exactly one JSON object on stdout with errors on stderr. Keep the field names `session_id`, `output`, `steps`, `usage`, `turn` from the start.
- Default tests must need no credentials or network: use recorded fixtures (e.g. SSE) and local mock servers. Live provider smoke tests are opt-in only and stay out of normal CI.
- Secrets come from environment variables or the OS keyring only. They must never appear in config files, logs, errors, tests, or commits, and secret-shaped values should be redacted in error and trace paths.
- Don't claim performance improvements without benchmarks.
